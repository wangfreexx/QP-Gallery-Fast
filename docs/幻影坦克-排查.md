# 双重图片（幻影坦克）排查

日期：2026-10-22　设备：192.168.1.3（Android 16）　应用：SwiftPic 1.9.0-patch1

## 结论

「重要图片」第一张确实就是用户放进去的那张，但它是**普通 JPEG，只有一层画面**，
不存在可切换的第二张图，应用不需要为它做任何处理。

- MediaStore：`_id=68844`，`/storage/emulated/0/Pictures/重要图片/Image_47918491586470_copy.jpg`，
  940×1200，`date_modified=1792654632`（最新，所以按日期排序排第一）
- File: `/storage/emulated/0/Pictures/QQ/Image_47918491586470.jpg`
- MD5 `500b4c107b7ddf2642bea49ae8c82528`，2,227,543 字节，与 QQ 目录里的原图**字节完全一致**
- 解码结果：JPEG / RGB，EXIF 条目数 0（连 EXIF 缩略图都没有）

## 为什么不是幻影坦克

幻影坦克（知乎问题 42093145 里说的那种）依赖 **带真实 alpha 的 PNG**：
同一批半透明像素叠在白底上显示图 A，叠在黑底上显示图 B。

这张图不满足前提：

1. JPEG 不支持 alpha 通道；文件里也没有第二段图像数据。
2. 结构上只有一条扫描：SOI → DQT(0xDB) → SOF0(0xC0) → DHT(0xC4) → SOS(0xDA)，
   文件以 `FFD9` 结束；`grep -abo 'MPF\|MotionPhoto\|MicroVideo'` 无结果。
3. EXIF 条目为 0，也排除了「内嵌缩略图与主图不同」那种做法。
4. 相册里的 3 个 PNG 虽然是 RGBA（color type 6），但 alpha 最小值 254/255，
   实际全部不透明，同样不是幻影坦克素材。

QQ 的「保存到相册」通常会把透明 PNG 压平成白底 JPEG，第二层在保存时就丢了；
如果 QQ 里缩略图和点开图不一致，那是 QQ 自己的缩略图缓存，不是这个文件里藏了东西。

另外当前查看器根布局是纯黑（`activity_viewer.xml:7`），首页网格跟随深色主题；
即便以后遇到真正的透明 PNG，两处也都只会看到黑底合成的那一层。

## 透明 PNG 实测（2026-10-25，Android 16，192.168.1.4）

用 600×600 RGBA 测试图（透明底、纯红方块、alpha=128 的蓝方块）验证当前行为：

- **网格**：透明区域取色 `rgb(5,5,5)` / `rgb(11,11,12)`，半透明蓝区域 `rgb(3,2,117)`
  ≈ alpha 128 蓝叠在黑底上的结果。说明 `MediaStore.loadThumbnail` 返回的缩略图
  已经被系统压平成不透明黑底，`item_photo.xml` 的 `colorSurfaceVariant` 底透不出来。
- **查看器**：根布局和 `ZoomImageView` 都是纯黑（`view_photo_page.xml:7,10`），
  透明区域显示黑色，半透明像素与黑色混合。全屏解码保留 alpha。

因此仅改网格控件底色不能恢复透明度；若要在网格里看到 alpha，需要绕开系统缩略图，
改用 `ImageDecoder` 解码原图生成缩略图。查看器则只需加白底/黑底切换。

测试图、`AlphaTest` 目录和 MediaStore 行已删除并重新 scan。

## 透明图背景设置（1.9.0-patch2）

设置 → 外观 → 透明图背景，可选「黑色 / 棋盘格」，默认黑色：

- 查看器：`ZoomImageView` 在图片显示范围下方绘制棋盘格（`CheckerPattern`），
  图片外仍是纯黑；缩放/平移时图案固定在屏幕坐标。
- 照片网格：PNG 先读 IHDR 判断 color type 是否为 4/6，只有带 alpha 的 PNG
  才用 `ImageDecoder` 解码缩略图（保留透明度），JPEG 和普通 RGB 截图仍走
  系统缩略图；`PhotoAdapter` 按设置给图片控件铺棋盘格底。
- 切换设置后返回相册会 `notifyDataSetChanged()` 重新绑定。

实测（patch2，Android 16）：棋盘格模式下，网格透明区域在
`rgb(27,31,37)` / `rgb(36,41,50)` 两色间交替，查看器图片内同样交替、图片外纯黑；
切回黑色后透明区域恢复 `rgb(5,5,5)`。测试探针已删除。
